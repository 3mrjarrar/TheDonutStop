# تفعيل لوحة الإدارة وحساب المالك

1. في Supabase → SQL Editor، شغّل `migrations/202609170002_admin_inventory.sql` مرة واحدة بعد ملف الجداول السابق.
2. في Authentication → إعدادات التسجيل، عطّل السماح بالتسجيل العام (Allow new users to sign up). الموظفون لا ينشئون حساباتهم من الموقع.
3. في Authentication → Users → Add user → Create new user، أنشئ حساب المالك بإيميله وكلمة مرور قوية تحفظها عندك. فعّل تأكيد الإيميل للحساب الذي تنشئه إداريًا. لا تشارك كلمة المرور هنا.
4. انسخ User UID للحساب، ثم شغّل التالي في SQL Editor بعد استبدال القيم:

```sql
insert into public.staff_profiles (user_id, name, role, active)
values ('REPLACE_WITH_USER_UUID'::uuid, 'اسم المالك', 'owner', true);
```

5. افتح `/admin` في نسخة الموقع التي تحتوي على هذه التغييرات، وسجّل الدخول.
6. اختر الفرع، ثم «تعديل المخزون» لإضافة كمية. اكتب سبب التعديل واضغط حفظ.

## استعادة كلمة المرور

أضف رابط `/admin` المحلي والرابط المنشور إلى Authentication → URL Configuration → Redirect URLs.
اضبط Site URL على عنوان الموقع المنشور. إعداد إرسال البريد عبر SMTP مطلوب للبريد الإنتاجي الموثوق؛ الإعداد الافتراضي ليس مناسبًا لإرسال رسائل إلى جميع الموظفين. اختبر وصول رابط الاستعادة وإمكانية تعيين كلمة مرور جديدة قبل الاعتماد عليه.

## الصلاحيات الحالية

- المالك يدير جميع الفروع.
- المدير يدير فقط الفروع المسجلة له في `staff_branches`.
- موظف الطلبات لا يستطيع تعديل المخزون.
- حتى لو عُدلت واجهة المتصفح، قاعدة البيانات ترفض عمليات غير المصرح لهم.
- الحساب المعطّل لا يستطيع إجراء تعديل جديد.
- كل تعديل يسجّل المستخدم والوقت والسبب والتغير والكمية الناتجة.
- إعادة إرسال العملية نفسها لا تضاعف المخزون؛ تعديل بناءً على كمية قديمة يُرفض حتى تحديث الشاشة.

إدارة حسابات الموظفين والدعوات من داخل الموقع، والطلبات والسلة، ليست جزءًا من هذه المرحلة. لا يوجد نموذج تسجيل عام.
